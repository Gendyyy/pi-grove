One card, four places to put the ledger

A card already says what the model did and how far along it is. It never says which files changed on disk. Four readings of the same card — same task, same four calls, same two files edited and one written — differing only in where the file signal lives and when it appears.

Footer ledger

one line, always on

The card gains a single dim line above its bottom border: a count, then the deduped paths, newest last. Derived on every repaint, so it grows while the card is still working. Clicking it opens a per-file ledger with line deltas.

Click the ↳ line — it expands into the full ledger in place.

Path column

dense, per row

The path stops being a summary and becomes a column: every write and edit row carries its own file and its own line delta, right where the change happened. The rollup gains a file count and the card gains no footer. Paths shorten from the left, so the basename always survives.

No summary anywhere — the answer is the rows. 3 files rides the rollup line.

Phase ledger

distributed into the plan

Files attach to the phase that changed them instead of to the card. A phase header carries its own files and deltas, so the plan itself becomes the ledger, and each phase states plainly that it changed nothing when it didn't.

Read it as a story: each phase says what it wrote, then shows the work that wrote it.

Commit stamp

silent until settled

While the card runs, nothing new appears. When the turn closes it, the card grows a closing block: a rule, a check, the totals, and the file list with deltas. Closer to a commit log than a status line, and it costs nothing mid-flight.

Two states, same card: still running above, settled below.

What all four keep

Same data, no new capture. Every write and edit row already stores its path in TreeNode.target, set for nested calls too. All four read the same deduped list; none of them needs a new event, a new snapshot field, or a replay change.

Same rules. Only write and edit count — files merely read are not touched. Paths are shortened from the left so the basename always survives, deduped per file, capped at three names with +K more, and the existing bottom-border click keeps its job: it still expands the card.

Same reading. Whatever the placement, one line answers "what did this turn change", and the deltas come from the diff the tool already produced.
